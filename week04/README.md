# [04주차] DevOps 핵심 요약 정리: 자동화, 협업 및 네트워크 기초

## 1. 리눅스 자동화 및 셸 스크립트
* **디렉터리 구조 감 잡기:** 시스템 전역 설정은 `/etc`, 로그는 `/var/log`, 임시 파일은 `/tmp`, 내가 만든 파일은 홈 디렉터리(`~`)에 위치함.
* **경로(Path)의 이해:**
  * **절대 경로:** 최상위 루트(`/`)에서 시작하는 전체 경로.
  * **상대 경로:** 현재 내 위치(`.`은 현재, `..`은 상위)를 기준으로 잡는 경로. 셸 스크립트에서 위치가 꼬이지 않도록 `cd "$(dirname "$0")"`를 활용해 스크립트 실행 위치를 기준점으로 잡는 것이 안전함.
* **검색 및 파이프(`|`):**
  * `find -type f -name "*.sh"`: 특정 확장자 파일 찾기
  * `grep -R -n "검색어" 디렉터리`: 하위 폴더까지 줄 번호(`-n`)와 함께 텍스트 검색
  * **파이프(`|`):** 앞 명령어의 표준 출력을 뒤 명령어의 표준 입력으로 전달 (예: `cat server.log | grep ERROR | wc -l`)
* **변수 선언 주의사항:** `USERNAME="홍길동"`처럼 `=` 기호 양쪽에 **공백이 절대 없어야 함**. 변수를 쓸 때는 반드시 `$USERNAME` 형태로 작성.
* **인자와 조건문:** `$#`는 인자 개수, `$1`은 첫 번째 인자를 의미하며, `[ -f 파일 ]`(존재 여부), `[ -z 문자열 ]`(빈 문자열 여부) 등을 통해 스크립트의 안정성을 높일 수 있음.

## 2. 프로세스 관리와 백업 자동화
* **프로그램 vs 프로세스:** 디스크에 정적으로 저장된 코드가 **프로그램**, 메모리에 적재되어 실행 중인 상태가 **프로세스**.
* **프로세스 제어 (`ps`, `kill`):**
  * `ps aux`: 실행 중인 모든 프로세스를 상세히 확인 (`a`: 모든 사용자, `u`: 사용자 중심 상세, `x`: 백그라운드 포함)
  * 명령어 뒤에 `&`를 붙이면 백그라운드 실행 가능 (`sleep 300 &`)
  * 프로세스 종료는 정상 종료 요청인 `kill <PID>` (`SIGTERM`, 번호 15)를 먼저 쓰고, 안 되면 강제 종료인 `kill -9 <PID>` (`SIGKILL`, 번호 9) 사용.
* **백업과 비교 (`tar`, `diff`):**
  * `tar -czf 백업명.tar.gz 원본폴더`: 압축 생성 (`c`: create, `z`: gzip, `f`: file)
  * `tar -xzf 백업명.tar.gz`: 압축 해제 (`x`: extract)
  * `diff -rq 원본 복원본`: 두 폴더를 재귀적으로 비교하여 차이점 확인 (0이면 동일)
* **`.gitignore` 활용:** 빌드 결과물이나 백업 폴더(`backups/`, `restore-check/`)는 깃 추적 대상에서 제외해야 함. 이미 추적 중이라면 `git rm --cached <파일명>`으로 해제 필요.

## 3. Git과 GitHub을 활용한 협업 (브랜치, PR, Conflict)
* **협업 흐름:** `main` (기준 브랜치) $\rightarrow$ `feature/기능명` (작업용 브랜치) $\rightarrow$ Commit & Push $\rightarrow$ **PR (Pull Request)** 요청 및 코드 리뷰 $\rightarrow$ Merge.
* **코드 충돌(Conflict) 해결하기:**
  * 동일 파일의 같은 라인을 서로 다르게 고쳤을 때 Git은 임의로 선택하지 못하고 충돌(`<<<<<<< HEAD`, `=======`, `>>>>>>>`)을 발생시킴.
  * 파일을 직접 열어 충돌 마크와 불필요한 코드를 정리한 뒤, `git add`와 `git commit`으로 해결 완료 처리를 해주면 됨.
* **메인 브랜치 보호:** 실무에서는 `main` 브랜치에 직접 푸시하는 것을 막고(Ruleset 또는 Branch Protection 설정), 반드시 PR을 거치도록 강제함.

## 4. 네트워크 기초 개념 (IP, 포트, DNS)
* **IP 주소와 포트:**
  * **IP 주소:** 네트워크상에서 컴퓨터를 찾아가는 집 주소 (공인 IP와 내부망에서만 쓰는 사설 IP로 나뉨. 공유기의 **NAT** 기술을 통해 사설 IP도 인터넷 통신 가능)
  * **포트(Port):** 컴퓨터 안에서 실행 중인 특정 프로그램(서비스)을 구분하는 번호 (예: SSH는 22, HTTP는 80, HTTPS는 443, MySQL은 3306)
* **DNS (Domain Name System):** 사람이 읽기 쉬운 도메인 이름(`cs.inhatc.ac.kr`)을 컴퓨터가 이해하는 IP 주소(`221.154.90.200`)로 변환해 주는 전화번호부 역할. (`dig`, `nslookup`으로 조회 가능)
* **TCP/IP 구조:** 응용 계층(HTTP, DNS) $\rightarrow$ 전송 계층(TCP/UDP, 포트 포장) $\rightarrow$ 인터넷 계층(IP 주소). TCP는 등기우편처럼 안전하고, UDP는 빠른우편처럼 속도가 빠름

## 5. 서버 실행 및 트러블슈팅 명령어
* **네트워크 및 상태 조회 툴:**
  * `ip addr`: 내 IP 주소 확인
  * `ping`: 상대방과의 통신 여부 확인 (방화벽 차단으로 응답이 없어도 서버가 죽은 것은 아님)
  * `curl -I <URL>`: 응답 헤더 및 HTTP 상태 코드(200, 404, 500 등) 확인
  * `ss -tlnp`: 현재 내 컴퓨터에서 TCP 포트가 어떤 상태로 대기(`LISTEN`) 중인지 프로세스 이름까지 확인. 실무에서 포트 충돌 해결 시 필수!
