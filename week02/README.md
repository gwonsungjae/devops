# 2주차 - 실습 환경 구축과 버전 관리 기초

## 💡 오늘 배운 핵심 내용

### 1. 서버와 가상화
- **서버의 개념**: 하드웨어(전원을 켜고 끄는 물리적 기기)와 소프트웨어(프로그램)의 의미를 모두 포함하고 있으며, 무언가를 제공하는 주체(`Server`)와 요청하는 주체(`Client`)의 구조로 동작함.
- **가상화 방식 비교**:
  - **베어메탈(Bare Metal)**: 물리 서버에 OS를 직접 설치해 사용. 구조가 단순하고 성능이 좋지만 격리가 안 되어 하나의 프로그램에 문제가 생기면 전체에 영향이 감.
  - **하이퍼바이저(VM)**: 호스트 OS 위에 하이퍼바이저를 얹고 가상 머신마다 게스트 OS를 실행. 격리가 강하지만 오버헤드가 큼.
  - **컨테이너(Docker 등)**: OS 커널을 호스트와 공유하면서 네임스페이스와 cgroups 기술로 격리된 공간을 만듦. 가볍고 빨라서 효율적임.

### 2. WSL2 + Ubuntu 리눅스 환경 구축
- 윈도우 환경에서 리눅스를 가볍게 쓸 수 있는 WSL2를 활용해 Ubuntu를 설치함.
- 학교 실습실처럼 여러 명이 쓰는 PC 환경에서는 `sudo adduser`로 본인 계정을 만들어 분리해서 사용하는 것이 안전함.

### 3. 꼭 써봐야 할 리눅스 명령어
- **파일/디렉터리**: `pwd`, `ls -al`, `mkdir`, `cd`, `cp`, `mv`, `rm`
- **권한 관리**: `chmod 755 파일명` (소유자 읽기/쓰기/실행, 그룹/기타 읽기/실행)
- **리다이렉션**: `>` (덮어쓰기), `>>` (이어쓰기), `cat` (파일 내용 합치기/보기)
- **기타 유용한 명령어**: 
  - `history`: 지금까지 입력한 명령어 기록 확인
  - `!!`: 직전 명령어 다시 실행 (`sudo` 빠뜨렸을 때 `sudo !!`로 유용하게 사용)
  - `tail -f 파일명`: 로그 파일 실시간 모니터링

### 4. Git과 GitHub 버전 관리
- **Git의 핵심 개념**: 코드 변경 이력을 스냅샷(커밋) 단위로 기록하는 도구.
  - `git init`: 현재 디렉터리를 깃 저장소로 만들기
  - `git add`: 스테이징 영역에 변경 사항 올리기 (파일을 저장하는 게 아니라 커밋에 포함할 후보로 지정하는 것)
  - `git commit -m "메시지"`: 하나의 버전으로 확정하기
  - `git switch -c 브랜치이름`: 브랜치 생성 및 이동
- **GitHub CLI (`gh`) 연동**:
  - `gh auth login`으로 터미널에서 깃허브 계정 인증
  - `gh repo create 레포이름 --public --source=. --remote origin --push` 한 줄로 로컬 저장소를 깃허브에 생성하고 푸시까지 완료하기

---

## 🛠️ 새로 알게 된 점 & 헷갈렸던 부분
- `git add`가 파일을 곧바로 깃에 저장하는 게 아니라, 다음 커밋을 위해 준비(Staging Area)하는 단계라는 점이 명확해졌다.
- `chmod`를 할 때 숫자가 4(읽기), 2(쓰기), 1(실행)의 합이라는 걸 알았으니 755나 750 권한 설정을 헷갈리지 않고 쓸 수 있을 것 같다.
- 학교 PC나 공용 컴퓨터를 쓸 때는 작업 후 반드시 `gh auth logout`을 해서 계정 정보를 지워야 안전하다는 것을 명심하자.# 2주차 - 실습 환경 구축과 버전 관리 기초
