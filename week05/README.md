# 5주차 - Docker 기초와 컨테이너 실습

## 💡 오늘 배운 핵심 내용

### 1. 도커(Docker)란 무엇인가?
- **개념**: 애플리케이션과 실행에 필요한 라이브러리, 설정 등을 하나의 **컨테이너(Container)**로 묶어 서로 다른 환경에서도 동일하게 실행할 수 있게 해주는 오픈 플랫폼.
- **"내 컴퓨터에서는 되는데요?" 문제 해결**: 앱뿐만 아니라 실행 환경 전체를 묶어 배송하기 때문에 개발자 노트북, 테스트 서버, 클라우드 등 어디서나 일관되게 동작함.
- **VM(가상 머신)과의 차이**:
  - **하이퍼바이저(VM)**: 하드웨어를 가상화하고 각각의 Guest OS를 실행하기 때문에 무겁고 느림.
  - **컨테이너**: 호스트 OS의 **커널을 공유**하면서 네임스페이스(시야 격리)와 cgroups(자원 제한) 기술로 프로세스 수준에서 격리하므로 가볍고 빠르게 시작됨.

### 2. 이미지와 컨테이너, 그리고 레지스트리
- **이미지(Image)**: 컨테이너를 만들기 위한 읽기 전용 템플릿 (붕어빵 틀에 비유).
- **컨테이너(Container)**: 이미지로부터 생성되어 실행 중인 인스턴스 (붕어빵). 삭제 시 쓰기 계층의 변경 사항은 사라짐.
- **Registry**: 이미지를 저장하고 공유하는 저장소 (예: Docker Hub).

### 3. 핵심 Docker 명령어
- `docker run`: 이미지를 다운받고 컨테이너를 생성 및 실행 (`-d` 백그라운드, `-p` 포트 연결, `--name` 이름 지정)
- `docker ps` / `docker ps -a`: 실행 중이거나 전체(정지된 것 포함) 컨테이너 목록 확인
- `docker logs -f <컨테이너>`: 컨테이너 로그를 실시간으로 모니터링
- `docker stop` / `docker start`: 컨테이너 정지 및 재시작
- `docker rm -f <컨테이너>`: 실행 중인 컨테이너 강제 삭제
- `docker exec -it <컨테이너> bash`: 실행 중인 컨테이너 내부로 들어가 셸 실행

## 🛠️ 혼자서 해보기 (실습 결과 기록)

### 1. 여러 개의 nginx 컨테이너 독립 실행 및 포트 포워딩
각각 다른 포트(`8091`, `8092`, `8093`)를 사용해 `nginx1`, `nginx2`, `nginx3` 컨테이너를 백그라운드로 띄웠다. 컨테이너 내부 포트는 모두 80으로 같지만, 호스트 포트가 분리되어 있어 충돌 없이 각각 격리된 네트워크 환경으로 동작한다.

### 2. 컨테이너 내부 `index.html` 수정 결과 (`curl` 테스트)
각 컨테이너의 내부(`exec`로 접속)로 들어가 `index.html`을 수정하여 브라우저와 터미널에서 각각 다르게 출력되도록 설정했다.

터미널에서 `curl`로 각 포트를 테스트한 결과는 다음과 같다:

```bash
home@DESKTOP-KQ330CJ:~/devops\$ curl http://localhost:8091
<h1>Welcome to nginx1</h1>
home@DESKTOP-KQ330CJ:~/devops\$ curl http://localhost:8092
<h1>Welcome to nginx2</h1>
home@DESKTOP-KQ330CJ:~/devops\$ curl http://localhost:8093
<h1>nginx3</h1>
